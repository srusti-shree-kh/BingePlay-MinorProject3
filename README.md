# BingePlay – Streaming Analytics Project

## 📌 Project Overview

BingePlay is a data analytics project based on a fictional OTT (Over-The-Top) streaming platform. The project uses SQL and Python to analyze subscription trends, revenue generation, user engagement, viewing behavior, content ratings, binge-watching patterns, and potential customer churn.

The main objective is to extract meaningful business insights from streaming platform data by answering 12 business questions using SQL queries and Python-based analysis.

## 🎯 Project Objectives

- Analyze subscription trends and revenue generation.
- Understand user engagement and viewing patterns.
- Identify popular shows based on ratings and viewing activity.
- Analyze binge-watching behavior among users.
- Evaluate subscription plan performance.
- Understand user conversion from signup to viewing.
- Identify potential customer churn signals.
- Apply SQL and Python to solve real-world business problems.

## 📂 Project Files

- **`README.md`** – Project overview, objectives, technologies, and execution instructions.
- **`bingeplay.ipynb`** – Jupyter Notebook containing Python code, SQL queries, data analysis, and results.
- **`bingeplay.sql`** – SQL script containing database creation, table definitions, data loading, verification queries, and analytical queries.

## 📊 Business Questions

The project addresses the following 12 business questions:

1. **Active Subscriptions and Revenue:** Analyze active subscriptions and revenue generated by subscription plans.
2. **Signup Trends:** Examine user signup trends over the analysis period.
3. **User Activity and Devices:** Understand user engagement and device usage patterns.
4. **Content Ratings and Performance:** Identify shows based on user ratings and viewing performance.
5. **Binge-Watching Behavior:** Analyze users' binge-watching patterns.
6. **Signup-to-Viewing Conversion:** Examine whether newly registered users begin watching content.
7. **Users Who Never Watched Content:** Identify users who signed up during Q1 but never started watching.
8. **Subscription Plan Suitability:** Evaluate whether subscription plans match user activity and viewing behavior.
9. **Subscription Upgrades:** Analyze users who upgraded their subscription plans.
10. **Cliffhanger Comebacks:** Investigate whether users return to watch shows after cliffhanger episodes.
11. **Consecutive-Week Engagement:** Identify users who remain engaged across consecutive weeks.
12. **Potential Churn Signals:** Identify viewing or subscription patterns that may indicate customer churn.

## ⚙️ How to Run the Project

### Step 1: Install the Required Tools

Install the following software:

- MySQL Server
- MySQL Workbench
- Python
- Jupyter Notebook

### Step 2: Install Python Libraries

Run the following command in your terminal or notebook:

```bash
pip install pandas sqlalchemy pymysql jupyter
```

### Step 3: Set Up the Database

1. Open MySQL Workbench.
2. Open the `bingeplay.sql` file.
3. Review the SQL script before executing it.
4. Execute the script to create the database, create the tables, load the data, and run the analytical queries.

**Important:** Check the SQL script before running it. If it contains `DROP DATABASE IF EXISTS bingeplay`, executing it will delete and recreate the existing `bingeplay` database. Back up any important data first.

### Step 4: Connect Python to MySQL

Open `bingeplay.ipynb` in Jupyter Notebook and configure the database connection.

```python
from sqlalchemy import create_engine
import pandas as pd

engine = create_engine(
    "mysql+pymysql://YOUR_USERNAME:YOUR_PASSWORD@localhost/bingeplay"
)
```

Replace `YOUR_USERNAME` and `YOUR_PASSWORD` with your MySQL credentials. Do not upload real database passwords or other sensitive credentials to GitHub.

### Step 5: Execute the Notebook

Run the notebook cells in sequence to connect to the database, execute SQL queries, retrieve results, and perform Python-based analysis.

**Note:** A local MySQL database is not automatically accessible from Google Colab. If using Colab, configure an accessible database connection or run the notebook locally.
